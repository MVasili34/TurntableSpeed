Код: `Estimators/GyroscopeSpeedEstimator.cs`, `Estimators/GyroZeroCalibrator.cs`

## 3.1. Физика MEMS-гироскопа и природа его ошибки

MEMS-гироскоп — это вибрирующая микромеханическая структура, измеряющая **силу Кориолиса**.
Внутри колеблется масса с известной скоростью `v`; при вращении корпуса с угловой
скоростью `ω` на массу действует

```
F_Кориолиса = −2m (ω × v)
```

Эта сила перпендикулярна колебанию и пропорциональна `ω`. Её ёмкостное отклонение
измеряется и переводится в рад/с.

Отсюда два фундаментальных типа ошибки:

### Ошибка нуля (bias)

Датчик выдаёт ненулевое значение при полной неподвижности. Причины: механические
несовершенства подвеса, паразитная ёмкостная связь, температурный дрейф. Величина —
единицы градусов в секунду у дешёвых сенсоров.

**Хорошая новость: это аддитивная ошибка, и её можно измерить.** Записать 2–3 секунды при
остановленном диске и усреднить.

### Ошибка масштабного коэффициента (scale factor)

Датчик выдаёт `ω_измер = k · ω_истин`, где `k ≠ 1`. Причины: разброс геометрии при
изготовлении, отклонение резонансной частоты вибрирующей структуры, температура.
Даташиты MEMS-гироскопов честно указывают **1–3 % (1σ) с завода**.

**Плохая новость: это мультипликативная ошибка, и на неподвижном диске её измерить
нельзя.** При `ω = 0` она никак не проявляется — `k·0 = 0`.

### Почему это убивает гироскоп как абсолютный измеритель

Мы измеряем отклонение скорости порядка **0.1–1 %**. Ошибка масштаба — **1–3 %**.
Инструмент имеет систематическую ошибку, в 10–30 раз превышающую измеряемую величину.

В центах: 2 % ошибки масштаба — это 34 цента, при том что цель сенсорного режима ±1.7
цента.

Это не значит, что гироскоп бесполезен. Он остаётся отличным измерителем **относительных
изменений**: масштабный коэффициент `k` постоянен в пределах измерения, поэтому детонация,
разгон, мгновенные колебания видны прекрасно. Плохо только абсолютное значение.

### Сравнение двух инструментов

| | Магнитометр | Гироскоп |
|---|---|---|
| Что измеряет | частоту (набег фазы) | амплитуду (силу Кориолиса) |
| Опорная величина | кварц телефона, единицы ppm | заводской масштабный коэффициент, 1–3 % |
| Частота дискретизации | 50–100 Гц | 200–500 Гц |
| Абсолютная точность | отличная | плохая |
| Отклик на изменения | медленный (нужна дуга) | мгновенный |
| Помехи | магнитные | вибрация |
| **Роль** | **опорный** | **вторичный, диагностический** |

## 3.2. Калибровка нуля

Код: `Estimators/GyroZeroCalibrator.cs`

Пользователя **активно просят** остановить диск и не трогать телефон 2.5 секунды. Дальше
покомпонентно:

```
bias = ( mean(ωₓ), mean(ω_y), mean(ω_z) )
σ    = ( sd(ωₓ),   sd(ω_y),   sd(ω_z)   )
```

Каждый входящий сэмпл потом корректируется: `ω_испр = ω_сырое − bias`.

### Проверка, что данные действительно неподвижны

Bias, снятый пока пользователь ещё опускал телефон на диск, **хуже, чем отсутствие bias
вообще**: он внесёт систематику, о которой никто не подозревает. Поэтому две проверки:

```
|bias| > 0.05 рад/с          → «диск ещё крутится»
max(σₓ, σ_y, σ_z) > 0.03     → «телефон держат в руках»
```

Первая ловит невыключенный диск (0.05 рад/с — это 0.5 rpm, заведомо меньше любого
номинала, но заведомо больше нуля исправного датчика). Вторая ловит дрожание рук: у
лежащего телефона шум гироскопа на порядок меньше.

При провале проверки UI обязан попросить повторить, а не тихо принять результат.
`Progress` (0..1) даёт индикатор набора нужных 2.5 с.

## 3.3. Ось вращения: не обязательно Z

Телефон лежит не идеально, ось вращения диска не совпадает с осью Z датчика. Вектор
угловой скорости `ω` направлен вдоль реальной оси вращения (всегда, по определению
угловой скорости твёрдого тела).

Здесь используется **среднее направление** (`PrincipalAxes.MeanDirection`), а не PCA:

```
ê = mean(ωᵢ) / |mean(ωᵢ)|
```

Разница принципиальна. У магнитометра вектор поля **вращается**, поэтому его среднее
неинформативно и нужна PCA (ищем плоскость). У гироскопа вектор `ω` **постоянен** — он
всё время смотрит вдоль оси вращения. Поэтому среднее и есть искомое направление, и — что
важно — **оно сохраняет знак**, а значит различает направление вращения. PCA знак теряет
(собственный вектор определён с точностью до знака).

Мгновенная скорость — проекция на эту ось:

```
ω_проекц(t) = ω(t) · ê
```

Проекция, а не модуль `|ω|`: модуль всегда положителен и складывает шум всех трёх осей,
завышая результат (для нулевой истинной скорости `E|ω_шум| > 0`). Проекция несмещённая и
знаковая.

## 3.4. Оценка скорости и её ошибка

```
ω̄ = mean(ω_проекц)
sd = std(ω_проекц)
```

### Статистическая составляющая

Соседние отсчёты гироскопа **коррелированы**: детонация, зубцовый момент, эксцентриситет
— это реальные физические колебания скорости, а не шум измерения. Как и у магнитометра,
вводится эффективная выборка:

```
ρ     = автокорреляция ω_проекц на лаге 1
n_эфф = n · (1 − ρ) / (1 + ρ)
SE_стат = sd / √n_эфф
```

Без этой поправки интервал сжимался бы как `1/√n` на данных, которые и близко не
независимы: при 400 Гц за 30 секунд `n = 12000`, и наивная формула дала бы фантастически
узкий интервал вокруг систематически смещённого значения.

### Систематическая составляющая — та самая, что доминирует

```
SE_масштаб = rpm · 0.02        (1σ = 2 %, пока не откалиброван)
```

Складываются в квадратуре (они независимы):

```
SE = √( SE_стат² + SE_масштаб² )
```

**Это самое важное место всего оценщика.** До калибровки `SE_масштаб` подавляет всё
остальное на порядки: при 33⅓ rpm это `±0.67 rpm`, тогда как `SE_стат` — тысячные доли.
Оценщик выдаёт честное «33.3 ± 0.7 rpm», и любое слияние по обратным дисперсиям
автоматически даст ему ничтожный вес против магнитометра с его `±0.02 rpm`.

Систематика не убирается усреднением — она не уменьшается со временем. Поэтому она
никогда не делится на `√n`.

Дополнительно — жёсткий потолок уверенности:

```
ceiling = IsScaleCalibrated ? 1.0 : 0.45
```

Абсолютное показание некалиброванного MEMS-гироскопа не заслуживает высокой уверенности,
как бы тихо ни выглядели данные.

## 3.5. Калибровка масштабного коэффициента по магнитометру

Код: `SensorFusionEstimator.CalibrateGyroScaleFactor`

Магнитометр даёт истинную `ω` без ошибки масштаба. Значит:

```
k = ω_магнитометр / ω_гироскоп_сырое
```

Три предохранителя, каждый обязателен:

1. **Опора должна быть точной.** Магнитометр допускается к калибровке только при
   относительной точности лучше 0.2 % (`SE/rpm < 0.002`). Иначе мы перенесём его шум в
   калибровку.

2. **Опора должна быть накоплена.** Требуется минимум 5 оборотов. За меньшее эксцентриситет
   диска не усреднился.

3. **Сырое показание, не откалиброванное.** В формулу берётся `omegaRawRadPerSecond` —
   значение **до** применения `ScaleFactor`. Иначе калибровка кормилась бы собой:
   применили `k`, измерили, получили `k' = k_маг/(k·ω) `, применили снова — и коэффициент
   уполз бы куда угодно.

4. **Санитарная проверка:** принимается только `0.9 < k < 1.1`. Отклонение больше ±10 % —
   это не ошибка масштабного коэффициента (она 1–3 %), это сломанное измерение: не тот
   датчик, не та ось, посторонняя вибрация.

После успешной калибровки `SE_масштаб` обнуляется, и гироскоп становится полноценным
измерителем. `ScaleFactor` показывается в диагностике — это интересная характеристика
конкретного экземпляра телефона.

## 3.6. Мгновенная скорость и разгон

### Мгновенная скорость

Скользящее среднее проекции за последнюю секунду (`SmoothingSeconds = 1.0`), умноженное на
`ScaleFactor`. Это то, что рисуется графиком `ω(t)` на экране.

### Трасса разгона

Параллельно ведётся сглаженная экспоненциальным фильтром трасса модуля `|ω|`:

```
α = 1 − exp(−Δt/τ),   τ = 0.2 с
ema ← ema + α·(|ω| − ema)
```

Форма `1 − exp(−Δt/τ)` вместо константы — потому что **сэмплы приходят неравномерно**.
Android-колбэки джиттерят, и фиксированный α давал бы разное эффективное сглаживание при
разном интервале. Эта форма — точное решение уравнения `dy/dt = (x − y)/τ` за шаг `Δt`,
поэтому постоянная времени остаётся ровно 0.2 с независимо от джиттера.

Трасса прореживается до 20 Гц — для измерения времени разгона разрешения 50 мс более чем
достаточно.

### Вычисление времени разгона

```
плато    = |ω̄|                                  (установившаяся скорость)
допуск   = плато · 1 % 
```

Ищется **последний** момент, когда скорость была вне полосы допуска; время разгона — это
следующий отсчёт после него.

Почему «последний выход», а не «первый вход»: диск может влететь в полосу и выскочить
обратно (перерегулирование пассика — обычное дело). Настоящее время выхода на номинал —
это момент, после которого скорость больше не покидала полосу.

Три случая, различаемые честно:

* `trace[0] > 0.5·плато` → запись началась с уже раскрученным диском → `null`, отчитываться
  не о чем;
* последний выход — это последний отсчёт → диск **ещё разгоняется** → `null`;
* иначе → время от первого сэмпла до входа в полосу.

## 3.7. Детонация (wow & flutter)

См. подробно [07-Детонация.md](07-Детонация.md). Кратко, что делает гироскопический
оценщик:

1. Ряд `ω_проекц(t)` пересэмплируется на равномерную сетку 100 Гц линейной интерполяцией
   (`UniformResampler`) — FFT требует равномерности, а сенсорные колбэки её не дают.
2. `WowFlutter.Analyze` переводит ряд в проценты от среднего, детрендит, применяет окно
   Ханна, делает FFT.
3. Из спектра берутся RMS в полосе 0.2–20 Гц и самый сильный компонент.

Ожидаемые пики и их физический смысл:

| Частота | Источник |
|---|---|
| `f_вращ` = 0.556 / 0.75 / 1.3 Гц | эксцентриситет диска, биение подшипника, несоосность отверстия |
| `f_шкива` | обороты вала мотора (обычно в разы выше) |
| `1/T_пассика` | неравномерность толщины пассика |

Гироскоп для этого подходит идеально: детонация — это **относительное** изменение
скорости, а на относительные изменения ошибка масштабного коэффициента не влияет (она
сокращается при делении на среднее).

## 3.8. Оценка уверенности

```
precision  = 1 − (SE/rpm)/0.01       // SE уже включает систематику масштаба
steadiness = 1 − (sd/ω̄)/0.10         // насколько ровно идёт диск
coverage   = n_эфф / 500             // накоплена ли статистика

confidence = (precision · steadiness · coverage)^(1/3) · ceiling
```

где `ceiling = 0.45` пока масштаб не откалиброван.

## 3.9. Итог

```
(t, ωₓ, ω_y, ω_z) @ 200–500 Гц
        ↓
   вычесть bias (GyroZeroCalibrator, 2.5 с на неподвижном диске)
        ↓
   TimeWindow 30 с
        ↓
   MeanDirection → ось вращения ê (со знаком)
        ↓
   проекция ω·ê → ряд скоростей
        ↓                            ↘
   среднее ω̄                          пересэмплинг 100 Гц → FFT → WowFlutter
        ↓                            ↘
   × ScaleFactor (от магнитометра)     трасса EMA → время разгона
        ↓
   SE = √(SE_стат² + SE_масштаб²)     ← систематика доминирует до калибровки
        ↓
   rpm ± SE, потолок уверенности 0.45 без калибровки
```
