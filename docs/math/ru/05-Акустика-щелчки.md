# 5. Акустика: автокорреляция щелчков — главный акустический метод

Код: `Estimators/ClickPeriodicityEstimator.cs`, `Dsp/Autocorrelation.cs`,
`Dsp/Envelope.cs`, `Dsp/Biquad.cs`, `Estimators/AudioProcessingDetector.cs`

---

## 5.1. Физика: почему щелчки — идеальный измеритель периода

Виниловая пластинка неидеальна. Пылинка в канавке, царапина, скол, износ — всё это даёт
короткий импульс на выходе звукоснимателя. Ключевое свойство:

> **Дефект физически привязан к конкретному месту на диске, поэтому игла проходит через
> него ровно раз за оборот.**

Это даёт последовательность импульсов с периодом, **точно равным периоду вращения**.
Никакой калибровки, никакого эталона, никаких предположений о содержимом записи.

Сравните с методами-конкурентами:

| Метод | Что нужно знать заранее |
|---|---|
| **Щелчки** | **ничего** |
| Анализ строя | как была настроена группа, как сведён мастеринг |
| Тестовая пластинка | нужна тестовая пластинка |

Щелчки работают на подводящей канавке, в паузах между треками и под музыкой — потому что
их спектр (импульс = широкополосный) отличается от спектра музыки в высокочастотной
области, и потому что они импульсны, а музыка стационарна.

Диапазон поиска лага 0.6–2.2 с покрывает 27–100 rpm, то есть все три номинала с большим
запасом на неисправный проигрыватель.

## 5.2. Предусловие: необработанный вход

Это **не деталь реализации, а условие работоспособности режима.**

Платформенная обработка микрофонного входа в Android спроектирована для голосовой связи и
делает ровно то, что нам смертельно:

| Обработка | Что делает | Почему смертельно |
|---|---|---|
| **Noise suppressor** | давит стационарный шум | щелчок — короткий нестационарный всплеск, попадает под определение «шум» |
| **AGC** | выравнивает уровень | ломает соотношение амплитуд щелчков, делает огибающую неинформативной |
| **Echo canceler** | адаптивная фильтрация | вносит переменную задержку — прямая порча периода |

Поэтому:

* Android: `MediaRecorder.AudioSource.Unprocessed` (при поддержке; проверять
  `PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED`), иначе `MIC`;
* явно отключить `NoiseSuppressor`, `AutomaticGainControl`, `AcousticEchoCanceler`;
* 44100 или 48000 Гц, моно, PCM.

### Но платформа может соврать

`AudioProcessingDetector` следит за **самим сигналом** и ищет отпечатки обработки.

**Отпечаток шумового гейта.** Гейт роняет тихие места до цифрового нуля. Микрофон в
комнате так не умеет — у него всегда есть акустический и тепловой шум.

```
noiseFloor  = 5-й перцентиль краткосрочного RMS (в дБ)
gateDepth   = медиана − noiseFloor
silentFrac  = доля кадров с RMS < 3e-5  (≈ −90 дБFS)

гейт подозревается, если:
    silentFrac > 2 %
  ИЛИ  (noiseFloor < −80 дБFS  И  gateDepth > 45 дБ)
```

Порог −80 дБFS: реальная комната через телефонный микрофон никогда не даёт такой тишины.

**Отпечаток AGC.** AGC держит долговременный уровень постоянным. Наивная проверка «мал ли
разброс медленного уровня» не работает: нужен масштаб для сравнения.

Правильный масштаб даёт сама арифметика сглаживания. Усреднение `w` кадров с разбросом σ
оставляет `σ/√w` **даже на идеально стабильном источнике**. Значит:

```
ожидаемый_медленный_σ = frameStd / √w
slowExcess            = slowStd / ожидаемый_медленный_σ
```

`slowExcess ≈ 1` означает, что долговременный уровень не несёт ничего сверх арифметики
сглаживания — это и есть след AGC. Реальный материал даёт в несколько раз больше.

```
AGC подозревается, если  slowExcess < 2.5  И  frameStd > 4 дБ
```

Второе условие обязательно: тест осмыслен только на материале, у которого есть что
выравнивать. На стационарном шуме он бы срабатывал ложно.

Плюс обычные проверки: клиппинг (`|x| ≥ 0.999` чаще чем 1e-4), слишком тихий сигнал
(RMS < −55 дБFS), постоянная составляющая (> 0.01), неожиданная частота дискретизации.

Различие `IsClean` / `IsUsable`: отказ платформы выставить флаг «unprocessed» сам по себе
не фатален — важно, выглядит ли сигнал обработанным на самом деле.

## 5.3. Шаг 1 — выделение огибающей щелчков

### Фильтр высоких частот 5 кГц, Butterworth 4-го порядка

Импульс имеет широкий спектр; музыка сосредоточена ниже. Отрезав всё ниже 5 кГц, мы
резко улучшаем отношение «щелчки/музыка».

Реализация — каскад биквадов (см. [09-DSP](09-DSP-примитивы.md) §3). Butterworth 4-го
порядка — это два звена второго порядка с добротностями

```
Q_i = 1 / (2·cos(π(2i+1)/(2N))),  N = 4  →  Q₀ = 0.5412, Q₁ = 1.3066
```

Порядок 4 даёт спад 24 дБ/октаву — на октаву ниже (2.5 кГц) музыка уже подавлена на 24 дБ.

Защита от устройств с низкой частотой дискретизации: срез ограничен `0.4·f_д`, чтобы не
уехать за Найквиста.

Фильтр **потоковый и сохраняет состояние между блоками** — иначе на каждой границе блока
возникал бы переходный процесс, то есть искусственный «щелчок» с периодом размера блока.
Это была бы катастрофа для метода. При разрыве в потоке (>50 мс или полблока) состояние
сбрасывается и окно очищается.

### RMS-огибающая, кадр 5 мс

```
env[j] = √( (1/H) Σ x²[jH .. jH+H−1] ),   H = round(f_д · 0.005)
```

`RmsEnvelopeFollower` принимает аудио блоками произвольного размера и выдаёт ровно один
отсчёт огибающей на каждые `H` входных отсчётов. Частота огибающей остаётся точно
`f_д/H` независимо от того, как платформа нарезает поток.

Выбор 5 мс — компромисс:

* короче → лучше временное разрешение, но больше шума в каждом кадре;
* длиннее → щелчок размажется и потеряет заметность над фоном.

Сырое разрешение по лагу равно 5 мс, что при периоде 1.8 с даёт 0.28 %. Этого мало для
цели ±0.3 %, поэтому обязательна субсэмпловая интерполяция пика (шаг 4).

Расчёт временных меток огибающей ведётся через **глобальный счётчик потреблённых
отсчётов**, а не накоплением локальных смещений: так метки не дрейфуют на длинных
записях.

### Альтернатива: преобразование Гильберта

В `Dsp/Envelope.cs` есть и точная аналитическая огибающая через Гильберта
(см. [09-DSP](09-DSP-примитивы.md) §5). Для этого оценщика используется RMS: она дешевле,
потоковая и даёт нужное прореживание бесплатно.

## 5.4. Шаг 2 — подавление стационарной составляющей

Огибающая содержит и музыку (стационарную), и щелчки (импульсные). Разделяем их бегущей
медианой:

```
residual[i] = env[i] − median(env[i−w/2 .. i+w/2]),   w = 0.25 с
residual[i] = max(0, residual[i])
```

**Почему медиана, а не среднее.** Медиана — робастная статистика: короткий сильный импульс
почти не сдвигает её. Скользящее среднее, наоборот, поднимется на месте щелчка и частично
вычтет его само из себя.

**Почему окно 0.25 с.** Оно должно быть сильно длиннее щелчка (5–20 мс), чтобы медиана его
не заметила, и сильно короче оборота (0.77–1.8 с), чтобы медиана успевала следить за
изменениями музыки. 0.25 с сидит ровно между.

**Почему отбрасываются отрицательные значения.** Провал огибающей ниже медианы — это
затухание музыки, а не щелчок. Информации о периоде вращения в нём нет, а в
автокорреляцию он вносил бы только шум. Отсечение по нулю к тому же превращает сигнал в
последовательность почти-дельт, у которой автокорреляция максимально острая.

Реализация бегущей медианы — через упорядоченный список с бинарным поиском:
`O(n·log w)`, отдельно обрабатывать края не нужно (окно зажимается).

## 5.5. Шаг 3 — автокорреляция

```
r(τ) = Σ_i residual[i]·residual[i+τ]
```

Считается через FFT по теореме Винера–Хинчина (спектр мощности ↔ автокорреляция):

```
X    = FFT(residual, дополненный нулями до 2^k ≥ n + maxLag + 1)
S    = |X|²
r    = IFFT(S)
```

Сложность `O(n log n)` вместо `O(n·maxLag)`. Дополнение нулями обязательно — иначе
получится **циклическая** автокорреляция, в которой конец записи «заворачивается» на
начало и создаёт ложные пики.

### Смещённая нормировка — сознательный выбор

Два варианта нормировки:

```
несмещённая:  r(τ) / (n − τ)     ← делим на число реально перекрывающихся отсчётов
смещённая:    r(τ) / n           ← делим на полную длину
```

В коде используется **смещённая**, и это принципиально.

Несмещённая формально корректнее (даёт несмещённую оценку автокорреляционной функции), но
у неё разрушительный побочный эффект: она **компенсирует уменьшение перекрытия**, из-за
чего гребёнка автокорреляции не затухает с лагом. Тогда пик на `2T` может оказаться выше
пика на `T` из-за случайных флуктуаций (на большом лаге оценка шумнее — усредняется меньше
слагаемых). Результат: **проигрыватель на 60 rpm читается как 30 rpm** — ровно вдвое
меньше.

Смещённая нормировка даёт естественный спад `(n−τ)/n`, который наклоняет гребёнку в
сторону коротких лагов. Истинный период выигрывает у своих кратных.

Затем всё делится на `r(0)`, так что `r(0) = 1` и величины сопоставимы между окнами.

Среднее вычитается перед вычислением — иначе постоянная составляющая дала бы огромную
параболу, на фоне которой пики не видны.

## 5.6. Шаг 4 — какой пик является периодом

Это самая сложная логика в оценщике, и она решает реальную проблему.

### Проблема гребёнки

Если на пластинке **c** дефектов, то щелчки идут с интервалом `s = T/c`, а не `T`.
Автокорреляция — это **гребёнка** с зубьями на кратных `s`, а не на кратных `T`.

Сырой максимум может попасть на любой зуб. Пример из комментария в коде: 45 rpm
(`T = 1.333 с`), три щелчка за оборот → `s = 0.444 с`. Максимум может оказаться на
`2s = 0.889 с`. Ни удвоение, ни деление пополам сюда не приведут: истинный период —
это `3s`, а максимум сидел на `2s`.

### Решение: сначала измерить шаг гребёнки

**Шаг 1. Найти все зубья.** Локальные максимумы автокорреляции, превышающие
`0.45 · сырой_пик`, уточнённые параболической интерполяцией.

**Шаг 2. Найти наибольший шаг `s`, кратными которого являются все зубья.** Это
вещественный аналог НОД. Перебираются делители кратчайшего зуба:

```
для divisor = 4, 3, 2, 1:
    s = кратчайший_зуб / divisor
    error = mean| зуб/s − round(зуб/s) |    по всем зубьям
выбирается s с минимальной error
```

Перебор делителей нужен потому, что **истинный шаг может быть короче минимального
исследуемого лага**: на 78 rpm с тремя щелчками за оборот `s = 0.769/3 = 0.256 с`, а
поиск начинается с 0.6 с. Без деления шаг никогда не был бы найден.

При точном равенстве побеждает первый испробованный делитель, то есть **самый мелкий шаг**.
Это безопасное направление: мелкий шаг лишь предлагает больше кандидатов, и каждый из них
всё равно обязан показать реальную автокорреляцию.

**Шаг 3. Кандидаты — кратные `s`.** Для каждого `m·s` уточняется локальный максимум в
окрестности ±30 мс, и считается «поддержка»:

```
support = высота_кандидата / высота_сырого_пика
```

Кандидаты с `support < 0.45` отбрасываются: там просто нет периодичности.

**Шаг 4. Ранжирование по сетке номиналов.**

```
score = support · (0.25 + 0.75 · уверенность_классификации(60/период))
```

Здесь используется независимая информация: **никакие два из периодов 1.8 / 1.333 / 0.769 с
не связаны малым целым отношением.**

```
1.8 / 1.333 = 1.35     1.8 / 0.769 = 2.34     1.333 / 0.769 = 1.73
```

Ни 2, ни 3, ни 3/2. Значит если кандидат попадает в сетку номиналов, а его гармоники —
нет, это сильное свидетельство.

Формула читается так: «support говорит, что периодичность здесь действительно есть; сетка
номиналов говорит, что на такой скорости проигрыватель действительно может работать».
Множитель `0.25` — минимальный вес: даже кандидат вне сетки не обнуляется, потому что
проигрыватель может быть сломан всерьёз.

**Шаг 5. Асимметрия в пользу короткого периода.** Кандидаты перебираются от коротких к
длинным, и длинный вытесняет короткий только при

```
score_длинного > score_короткого · 1.1
```

Обоснование: пик на `2T` — это гармоника периода, а не период. Ошибка «вдвое медленнее»
гораздо вероятнее ошибки «вдвое быстрее», и запас 10 % от неё страхует.

## 5.7. Шаг 5 — субсэмпловое уточнение и порог обнаружения

### Параболическая интерполяция

Сырое разрешение — 5 мс, то есть 0.28 % при 1.8 с. Недостаточно. Через три точки вокруг
максимума проводится парабола (см. [09-DSP](09-DSP-примитивы.md) §4):

```
a = ½(y₋₁ + y₊₁) − y₀
b = ½(y₊₁ − y₋₁)
δ = −b/(2a)          смещение вершины, в отсчётах
A = y₀ + ½·b·δ       высота
c = −a               кривизна
```

Это поднимает разрешение примерно на порядок.

### Порог «пик или не пик»

```
noiseFloor = std(автокорреляция вне ±50 мс от пика)
если  пик / noiseFloor < 5  →  оценщик молчит
```

Бугорок в три-четыре сигмы над фоном — это флуктуация, а не обнаружение. Лучше продолжать
молчать, чем опубликовать период, выуженный из шума, да ещё с узким интервалом вокруг
него. Это прямое следствие принципа «любая цифра сопровождается честной
неопределённостью».

## 5.8. Неопределённость периода

Три независимых механизма, и берётся **худший из трёх** — потому что они не усредняют друг
друга.

### 1. Фоновый разброс

Возмущение `ε` значений автокорреляции сдвигает вершину параболы на величину порядка
`ε/(2c)`, где `c` — кривизна. Фон автокорреляции и есть это возмущение:

```
σ₁ = noiseFloor / (2·кривизна) · Δt_огибающей
```

### 2. Джиттер щелчков

Дефект имеет конечную протяжённость, эксцентриситет пластинки смещает момент прохода — пик
получает конечную полуширину `w`. Из формы параболы `y ≈ A − c·x²`, где на полуширине
значение падает вдвое:

```
c = A/(2w²)   →   w = √(A/(2c))
```

Центр пика, построенного по `N` оборотам, локализуется как

```
σ₂ = w · √2 / √N · Δt_огибающей
```

Это доминирует на изношенной или эксцентричной пластинке.

### 3. Смещение интерполяции — систематика

Пик автокорреляции шириной в один-два кадра **не является параболой**. Подгонка параболы
к непараболе тянет ответ к сетке отсчётов на фиксированную долю кадра, сколько бы ни
длилась запись:

```
σ₃ = 0.15 · Δt_огибающей       (0.15 измерено на синтетических щелчках)
```

Это **систематическая** ошибка. Она не уменьшается с накоплением данных, поэтому образует
**пол** отчётной неопределённости. Оценщик не имеет права заявить точность лучше, чем
позволяет метод интерполяции, как бы долго он ни работал.

```
σ_T = max(σ₁, σ₂, σ₃)
```

### Перенос на rpm

```
n = 60/T   →   dn/dT = −60/T² = −n/T
σ_n = (n/T) · σ_T
```

---

## 5.9. Оценка уверенности

```
precision   = 1 − (σ_n/n)/0.003 · 0.5        цель ±0.3 %
prominence  = (пик/фон − 4)/8                ниже 4σ — не пик, к 12σ — несомненно
coverage    = обороты/12
unambiguous = 1 − |support − 1|·0.5          выбранный над соперником — менее уверен

confidence = (precision · prominence · coverage · unambiguous)^(1/4)
```

Снова геометрическое среднее: любой провалившийся фактор тянет результат вниз.

```
   σ_T = max(фон, джиттер, смещение интерполяции)
        ↓
   n = 60/T ± (n/T)·σ_T
```
