# 8. Неопределённость и слияние оценок

Код: `Contracts/SpeedEstimate.cs`, `Estimators/SensorFusionEstimator.cs`,
`Estimators/AudioFusionEstimator.cs`, `Dsp/LineFit.cs`

---

## 8.1. Принцип: точечное значение без интервала бессмысленно

Задача — измерить отклонение в 0.1–1 % инструментами, у которых собственные систематики
достигают 1–3 %. В таких условиях число «33.28 rpm» само по себе не несёт информации:
всё решает, `± 0.01` это или `± 0.7`.

Поэтому в архитектуру заложено: **`SpeedEstimate` невозможно построить без
`StandardError`**. Это поле записи, а не опция.

```csharp
Margin95    = 1.959964 · StandardError      // z_{0.975}
LowerBound95 = rpm − Margin95
UpperBound95 = rpm + Margin95
```

Нормальность оправдана: все оценки — это либо наклон регрессии по сотням точек, либо
среднее по многим отсчётам. Работает ЦПТ.

## 8.2. Три источника неопределённости и их разная природа

### Статистическая — уменьшается с накоплением

```
σ_стат ~ 1/√n
```

Шум датчика, фон автокорреляции, разброс кадров. Копи данные дольше — станет точнее.

### Систематическая — не уменьшается никогда

| Источник | Величина | Где |
|---|---|---|
| Масштаб гироскопа | 2 % (1σ) | [03](03-Гироскоп.md) |
| Строй записи | 15 центов ≈ 0.87 % | [06](06-Акустика-строй.md) |
| Смещение параболической интерполяции | 0.15 кадра | [05](05-Акустика-щелчки.md) |

Эти величины **не делятся на √n никогда**. Они складываются в квадратуре со
статистической и часто её полностью подавляют:

```
σ = √(σ_стат² + σ_сист²)
```

Пример: гироскоп при 33⅓ rpm за 30 секунд даёт `σ_стат ≈ 0.001 rpm`, а
`σ_сист = 33.33·0.02 = 0.67 rpm`. Итог — 0.67. Статистика не видна вообще.

Это не пессимизм, а честность. Занизить интервал здесь означало бы выдать заведомо
неверный результат за точный.

### Корреляция остатков — маскируется под статистическую

Самая коварная категория. Формула `σ/√n` верна **только для независимых наблюдений**.
Реальные данные коррелированы:

* фаза магнитометра — медленное магнитное блуждание;
* скорость гироскопа — детонация и зубцовый момент это реальные колебания;
* кадры анализа строя — перекрываются на 40 %.

Игнорирование даёт формально узкий, но фактически неверный интервал.

**Лечение через эффективный размер выборки.** Для процесса AR(1) с коэффициентом `ρ`
дисперсия среднего в `(1+ρ)/(1−ρ)` раз больше, чем у белого шума. Отсюда:

```
ρ     = автокорреляция остатков на лаге 1
n_эфф = n · (1 − ρ)/(1 + ρ)
σ     = σ_наивная · √(n/n_эфф)
```

| ρ | n_эфф / n | раздувание σ |
|---|---|---|
| 0.0 | 1.00 | ×1.00 |
| 0.3 | 0.54 | ×1.36 |
| 0.5 | 0.33 | ×1.73 |
| 0.8 | 0.11 | ×3.00 |
| 0.9 | 0.053 | ×4.36 |

При `ρ ≤ 0` коррекция не применяется — отрицательная корреляция сузила бы интервал, и
пользоваться этим было бы оптимистично.

Для перекрывающихся кадров используется прямой аналог: считаются не все кадры, а
`span / длительность_кадра`, то есть число непересекающихся.

## 8.3. Перенос неопределённости через преобразования

Везде применяется линеаризация (delta-метод): `σ_y = |dy/dx| · σ_x`.

| Преобразование | Производная | Формула σ |
|---|---|---|
| `rpm = ω·60/2π` | `60/2π` | `σ_rpm = σ_ω · 60/2π` |
| `rpm = 60/T` | `−60/T² = −rpm/T` | `σ_rpm = (rpm/T)·σ_T` |
| `rpm = f·60` | `60` | `σ_rpm = σ_f · 60` |
| `rpm = N·2^(c/1200)` | `N·(ln2/1200)·2^(c/1200)` | `σ_rpm = N·(ln2/1200)·2^(c/1200)·σ_c` |

Первые три линейны, поэтому перенос точен. Четвёртое — экспоненциально, и производная
берётся **в точке измерения**, а не как константа. При отклонениях в единицы процентов
разница уже видна.

## 8.4. Уверенность (Confidence) — это не то же самое, что σ

Две разные величины, отвечающие на разные вопросы:

| | σ (StandardError) | Confidence |
|---|---|---|
| Вопрос | «насколько разбросано число» | «применим ли метод вообще» |
| Единицы | rpm | безразмерная 0..1 |
| Считается | из статистики | эвристически, из диагностик |

Confidence ловит то, что σ поймать не может: телефон не в плоскости вращения, эллипс не
подогнался, пик автокорреляции не выше фона, в кадре нет тональной музыки. Формально σ
могла бы быть маленькой, а результат — мусором.

**Везде используется геометрическое среднее** частных факторов:

```
confidence = (f₁ · f₂ · ... · f_k)^(1/k)
```

Обоснование: одна провалившаяся компонента должна утянуть результат вниз, а не быть
усреднённой с остальными хорошими. Арифметическое среднее пяти факторов
`(0, 1, 1, 1, 1)` даёт 0.8 — абсурд. Геометрическое даёт 0.

Дополнительно — **жёсткие потолки** там, где метод принципиально ограничен:

```
гироскоп без калибровки масштаба:  ceiling = 0.45
оценщик строя (всегда):            ceiling = 0.50
```

И общий множитель от классификации номинала:

```
Confidence_итог = Confidence_оценщика · (0.35 + 0.65 · Confidence_классификации)
```

## 8.5. Слияние сенсоров: НЕ усреднение

Код: `SensorFusionEstimator`

Здесь сознательно **нет** слияния по обратным дисперсиям. Причина:

> Магнитометр и гироскоп не равноправны. У гироскопа систематика 2 %, у магнитометра её
> нет по построению. Усреднять их — значит подмешивать заведомо смещённую оценку в
> несмещённую.

Правило простое: **магнитометр побеждает всегда, когда у него есть ответ.** Гироскоп
подменяет его, только если магнитометра нет физически — и тогда его 2 % уже сидят в его σ,
так что пользователь видит честный широкий интервал.

Роль гироскопа — три вещи, которых магнитометр не умеет:

1. мгновенная `ω(t)` (высокая частота дискретизации);
2. спектр детонации;
3. время разгона.

### Что делается с расхождением

```
disagreement = (rpm_гиро_СЫРОЙ − rpm_маг) / rpm_маг · 100
```

Сырой — то есть до применения `ScaleFactor`. Сравнивать откалиброванный было бы порочным
кругом: калибровка приравняла бы их по определению.

При `|disagreement| > 2 %`:

* поднимается флаг `MethodsDisagree`;
* уверенность умножается на 0.4;
* **само значение магнитометра не трогается.**

Это принципиально: расхождение — это **информация о том, что что-то не так** (магнитная
помеха, телефон скользит, вибрация), а не повод усреднить и получить нечто среднее между
правильным и неправильным.

### Калибровка масштаба

```
k = ω_маг / ω_гиро_сырое
```

при трёх условиях: точность магнитометра лучше 0.2 %, накоплено ≥ 5 оборотов, результат в
пределах `0.9 < k < 1.1`. Подробности в [03](03-Гироскоп.md) §5.

## 8.6. Слияние акустических методов: слияние по обратным дисперсиям

Код: `AudioFusionEstimator`

Здесь ситуация другая: три метода **независимы и не имеют общих механизмов отказа**.

| Метод | Механизм | Отказывает при |
|---|---|---|
| Автокорреляция щелчков | импульсы от дефектов | идеально чистой пластинке в тихом месте |
| Сетка полутонов | равномерная темперация | атональной музыке, ударных, шуме |
| Спектр детонации | модуляция от эксцентриситета | идеально отцентрованной пластинке |

Ни один из этих отказов не влечёт другой. Значит их **согласие — сильнейшее доступное
свидетельство надёжности**, и объединять их осмысленно.

### Математика слияния

Для независимых оценок `xᵢ ± σᵢ` минимальную дисперсию даёт взвешивание по обратным
дисперсиям (это МНК-оптимум и одновременно максимум правдоподобия для гауссиан):

```
wᵢ = 1/σᵢ²
x̂  = Σ wᵢxᵢ / Σ wᵢ
σ̂  = 1/√(Σ wᵢ)
```

Замечательное свойство: `σ̂` **меньше любого из отдельных σᵢ**. Два независимых измерения
с равной точностью дают комбинацию в `√2` раз точнее.

Автоматически получается правильная иерархия. Пусть автокорреляция даёт
`33.33 ± 0.10 rpm`, а строй — `33.30 ± 0.29` (15 центов систематики):

```
w₁ = 1/0.01 = 100        w₂ = 1/0.084 = 11.9
x̂ = (100·33.33 + 11.9·33.30)/111.9 = 33.327
σ̂ = 1/√111.9 = 0.095
```

Строй сдвинул результат на 0.003 rpm и чуть сузил интервал. Ровно та роль, которой он
заслуживает: систематика в 15 центов, честно внесённая в σ, сама по себе поставила его на
место. Никаких ручных приоритетов не понадобилось.

### Предохранитель: сливаются только согласные

```
disagreement = (rpm_строй − rpm_щелчки)/rpm_щелчки · 100
```

При `|disagreement| > 1 %` оценщик строя **исключается из комбинации**, поднимается флаг
`MethodsDisagree`, уверенность умножается на 0.4. Спектр детонации проходит ту же проверку
на согласованность.

Порог 1 % при акустической цели 0.3 % — с запасом за пределами ожидаемого разброса.

### Бонус за согласие

```
if (parts.Count > 1) confidence *= 1.15;
```

Согласие механизмов, не имеющих общих причин отказа, — это самое сильное свидетельство,
которое можно получить не выходя за пределы задачи (спецификация §4.5). Ему позволено
повысить уверенность. Противоречие делает обратное и не заминается.

Реализация выбирает эталон (`click ?? pitch`), добавляет к нему согласных, и делает
слияние. Уверенность комбинации берётся как **максимум** из частных (комбинация не хуже
лучшего из вошедших), после чего применяются бонус и штраф.

## 8.7. Расхождение двух режимов — тоже результат

Финальный уровень. Сенсорный режим измеряет скорость **с телефоном на диске** (150–250 г
дополнительной массы на подшипник). Акустический — скорость при обычном воспроизведении.

```
Δ = (rpm_акустика − rpm_сенсоры) / rpm_сенсоры · 100
```

Это **не ошибка и не шум**: это количественная характеристика того, насколько привод
проседает под дополнительной нагрузкой. Отрицательная Δ на пассиковом приводе означает,
что телефон реально притормаживает диск.

Спецификация требует показывать эту величину пользователю, а не прятать. Она отвечает на
вопрос, ради которого вообще сделано два режима.

## 8.8. Сводка всех источников неопределённости

| Метод | Статистика | Систематика | Корреляция | Типичная итоговая σ |
|---|---|---|---|---|
| Магнитометр | SE наклона регрессии (Хьюбер, τ-масштаб) | — | ρ остатков фазы | 0.02–0.05 % |
| Гироскоп | `sd/√n_эфф` | **2 % масштаба** | ρ ряда скорости | 2 % до калибровки |
| Щелчки | фон АКФ, джиттер | **0.15 кадра интерполяции** | — | 0.1–0.3 % |
| Строй | `σ_кругл/√n_непересек` | **15 центов строя записи** | перекрытие кадров | ~0.9 % |
| Спектр детонации | фон в полосе / кривизна | — | — | 0.3–1 % |
