# 9. DSP-примитивы: математика строительных блоков

Код: `TurntableSpeed.Core/Dsp/`

Здесь собраны выводы для всех вспомогательных численных методов. Каждый из них покрыт
отдельными тестами (спецификация §7.3), потому что ошибка в примитиве проявляется как
необъяснимая систематика на верхнем уровне.

---

## 9.1. FFT и нормировка

Код: `Dsp/Fft.cs` (обёртка над `MathNet.Numerics`)

### Соглашение о нормировке

Прямое преобразование — без масштабирования; обратное делится на N, так что
`IFFT(FFT(x)) = x`.

Односторонний амплитудный спектр строится так, чтобы **синус амплитуды A, попадающий
ровно в бин k, читался как A**:

```
X_k = Σ_{n=0}^{N−1} x_n · e^{−2πikn/N}

|A_k| = |X_k| · 2/N        для 0 < k < N/2
|A_k| = |X_k| · 1/N        для k = 0 (DC) и k = N/2 (Найквист)
```

Множитель 2 для средних бинов — потому что энергия вещественного синуса делится поровну
между `+f` и `−f`. DC и Найквист не имеют пары, поэтому не удваиваются.

### Частотная сетка

```
f_k = k · f_д / N
Δf  = f_д / N        разрешение
```

Разрешение обратно пропорционально **длительности** записи `T = N/f_д`:

```
Δf = 1/T
```

Отсюда цифра из [07](07-Детонация.md): 3 минуты → 0.0056 Гц.

### Оконные функции

```
Прямоугольное:  w = 1
Ханна:          w = 0.5 − 0.5·cos(2πi/(N−1))
Хэмминга:       w = 0.54 − 0.46·cos(2πi/(N−1))
Блэкмана:       w = 0.42 − 0.5·cos(2πi/(N−1)) + 0.08·cos(4πi/(N−1))
```

**Зачем окно.** FFT неявно считает сигнал периодическим на длине блока. Если начало и
конец не стыкуются, возникает разрыв, чей спектр — это `1/f`, размазанный по всем бинам
(«растекание спектра»). Окно плавно сводит края к нулю и убирает разрыв.

Цена — уширение главного лепестка. Ханна: главный лепесток вдвое шире прямоугольного,
зато боковые падают на 31 дБ вместо 13 и спадают как `1/f³` вместо `1/f`. Для наших задач
(поиск слабой линии рядом с сильной) это правильный размен.

**Когерентное усиление** — среднее значение окна:

```
CG = (1/N) Σ wᵢ        Ханна: 0.5
```

Окно ослабляет сигнал в CG раз, поэтому амплитуды делятся на CG. Без этого все амплитуды
были бы занижены вдвое.

**Дополнение нулями** не добавляет информации (разрешение по-прежнему `1/T_данных`), но
интерполирует спектр, что помогает параболической интерполяции пика. Оно разбавляет
амплитуду в `N_дополн/N_данных` раз, что компенсируется явно:

```
correction = (N_дополн / N_данных) / CG
```

## 9.2. Автокорреляция через FFT

Код: `Dsp/Autocorrelation.cs`

Теорема Винера–Хинчина: автокорреляционная функция и спектральная плотность мощности —
пара Фурье.

```
r(τ) = IFFT( |FFT(x)|² )
```

Сложность `O(N log N)` вместо `O(N·maxLag)`.

**Дополнение нулями обязательно** до `N + maxLag + 1`. Без него получается циклическая
автокорреляция: конец записи «заворачивается» на начало и создаёт ложные пики. Нужна
линейная.

Нормировки — см. [05](05-Акустика-щелчки.md) §5. Кратко: используется **смещённая**
(деление на `n`, а не на `n−τ`), потому что её естественный спад `(n−τ)/n` не даёт
кратным периодам обогнать истинный.

## 9.3. Биквады и фильтры Butterworth

Код: `Dsp/Biquad.cs`

### Транспонированная прямая форма II

```
y[n] = b₀·x[n] + z₁
z₁   = b₁·x[n] − a₁·y[n] + z₂
z₂   = b₂·x[n] − a₂·y[n]
```

Выбрана из-за лучшей численной устойчивости при работе в double и минимума состояния (два
регистра). Состояние сохраняется между блоками — **обязательно** для потокового аудио,
иначе на каждой границе блока возникал бы переходный процесс, то есть искусственный щелчок
с периодом размера блока.

### Расчёт по RBJ cookbook

```
ω₀ = 2π·f_срез/f_д
α  = sin(ω₀)/(2Q)

ФНЧ:  b = [(1−cos ω₀)/2,  1−cos ω₀,  (1−cos ω₀)/2]
ФВЧ:  b = [(1+cos ω₀)/2, −(1+cos ω₀), (1+cos ω₀)/2]
оба:  a = [1+α, −2cos ω₀, 1−α]
```

Билинейное преобразование с предыскажением частоты, так что точка −3 дБ попадает ровно на
запрошенную цифровую частоту.

### Добротности секций Butterworth

Фильтр Butterworth порядка N имеет полюса, равномерно расположенные на левой половине
единичной окружности в s-плоскости. Разбивая на секции второго порядка, для i-й секции:

```
Qᵢ = 1 / (2·cos(π(2i+1)/(2N)))
```

Для N = 4:

```
Q₀ = 1/(2·cos(π/8))  = 0.5412
Q₁ = 1/(2·cos(3π/8)) = 1.3066
```

Каскад двух таких секций даёт максимально плоскую АЧХ в полосе пропускания и спад
24 дБ/октаву.

Проверка АЧХ (используется в тестах) — через комплексный отклик:

```
H(f) = (b₀ + b₁z⁻¹ + b₂z⁻²) / (1 + a₁z⁻¹ + a₂z⁻²),   z⁻¹ = e^{−2πif/f_д}
```

Модули секций перемножаются.

## 9.4. Параболическая интерполяция пика

Код: `Dsp/PeakInterpolation.cs`

### Вывод

Через три равноотстоящие точки `(−1, y₋₁)`, `(0, y₀)`, `(+1, y₊₁)` проходит единственная
парабола `y = ax² + bx + c`:

```
c = y₀
a + b + c = y₊₁        →   a = ½(y₋₁ + y₊₁) − y₀
a − b + c = y₋₁            b = ½(y₊₁ − y₋₁)
```

Вершина в `x* = −b/(2a)`, значение в вершине:

```
y* = a·x*² + b·x* + y₀ = −b²/(4a) + y₀ = y₀ + ½·b·x*
```

Кривизна `c_кривизна = −a` (положительна для максимума, поскольку `a < 0`).

Смещение зажимается в [−1, 1]: больше означает, что максимум не в центральной точке, то
есть выбор точек был неверен.

### Чувствительность к шуму

Возмущение значений на `ε` сдвигает вершину. Из `x* = −b/(2a)`, возмущение `b` на `Δb`
даёт `Δx* = −Δb/(2a) = Δb/(2c_кривизна)`. Отсюда общая оценка порядка величины:

```
Δx* ~ ε / (2·кривизна)
```

Это ровно та формула, которая переводит шум автокорреляции и шум спектра в
неопределённость периода ([05](05-Акустика-щелчки.md) §8) и частоты
([07](07-Детонация.md)). Острый пик (большая кривизна) локализуется точно, пологий — нет.

### Полуширина из высоты и кривизны

Для `y = A − c·x²` полуширина `w` (где значение падает вдвое) удовлетворяет `c·w² = A/2`:

```
w = √(A / (2c))
```

Используется для оценки джиттера щелчков.

### Смещение при негауссовой форме пика

Пик автокорреляции щелчков шириной в один-два кадра **не является параболой**. Подгонка
параболы к непараболе даёт систематическое притяжение к сетке отсчётов — измерено как
0.15 кадра. Это систематика, она не уменьшается с накоплением данных и образует пол
неопределённости.

Для спектральных пиков ситуация лучше: главный лепесток окна Ханна в **логарифмическом**
масштабе близок к параболе. Поэтому в `PitchGridEstimator` интерполяция делается по
`log(амплитуда)`, а не по амплитуде.

## 9.5. Преобразование Гильберта и аналитический сигнал

Код: `Dsp/Envelope.cs`

Аналитический сигнал вещественного `x(t)`:

```
z(t) = x(t) + i·H{x}(t)
```

где `H` — преобразование Гильберта (фазовый сдвиг всех частот на −90°). В частотной
области это тривиально:

```
Z(f) = 2·X(f)   для f > 0
Z(f) = X(f)     для f = 0 и f = Найквист
Z(f) = 0        для f < 0
```

Отсюда реализация: FFT → обнулить отрицательные частоты, удвоить положительные → IFFT.

Из аналитического сигнала:

```
огибающая        = |z(t)|
мгновенная фаза  = arg z(t), развёрнутая
мгновенная частота = d(фаза)/dt / 2π
```

В проекте используется как точный (неблоковый) вариант огибающей и как эталон для тестов
RMS-огибающей. В боевом пути щелчков применяется RMS: она дешевле, потоковая и даёт
прореживание бесплатно.

## 9.6. Ресемплинг

Код: `Dsp/Resampling.cs`

### Линейный — для сенсорных данных

`UniformResampler` кладёт неравномерно размеченные сэмплы на равномерную сетку линейной
интерполяцией. Нужен потому, что Android-колбэки джиттерят, а любой FFT ниже по потоку
предполагает равномерность.

Шаг сетки по умолчанию — **медианный** интервал входа. Медиана, а не среднее: один
пропущенный сэмпл удваивает интервал и портит среднее, но не медиану.

Линейная интерполяция вносит небольшое НЧ-подавление (АЧХ — `sinc²`), но при
передискретизации в разы (сенсор 200–400 Гц → сетка 100 Гц, полоса интереса до 20 Гц) это
пренебрежимо.

### Ланцоша — для симуляции ошибки скорости

`Resampler.ChangeSpeed` меняет скорость воспроизведения. Используется в тестах: сгенерировать
сигнал, «проиграть» его в 1.01 раза быстрее и проверить, что оценщик увидит ровно +1 %.

Ядро Ланцоша — оконный sinc:

```
L(x) = sinc(x)·sinc(x/a)   при |x| < a
     = 0                    иначе

где sinc(x) = sin(πx)/(πx),  a = число лепестков (8 по умолчанию)
```

sinc — идеальный интерполятор для сигналов с ограниченным спектром (теорема
Котельникова); умножение на второй sinc ограничивает ядро конечной длиной с приемлемыми
артефактами.

**Защита от алиасинга.** При ускорении спектр сжимается к Найквисту, и часть его выходит
за границу. Поэтому ядро растягивается:

```
kernelScale = max(1, speedFactor)
w = L((position − k)/kernelScale, a)
```

Растянутое во времени ядро = суженное по частоте = встроенный антиалиасинговый фильтр.

Веса нормируются суммой (`sum/weightSum`), что убирает мелкую пульсацию усиления от
обрезки ядра на краях.

Физика соответствия:

```
воспроизведение в s раз быстрее  →  длина × 1/s  →  высота +1200·log₂(s) центов
```

## 9.7. Робастная статистика

Код: `Dsp/SeriesMath.cs`

### Медиана и перцентили

Линейно интерполированный перцентиль: позиция `p·(n−1)`, интерполяция между соседями.

### Медианное абсолютное отклонение

```
MAD = 1.4826 · median|xᵢ − median(x)|
```

Множитель `1.4826 = 1/Φ⁻¹(0.75)` делает MAD **состоятельной оценкой σ** для нормальных
данных: у стандартного нормального медиана `|x|` равна 0.6745, и `1/0.6745 = 1.4826`.

Точка слома MAD — 50 %: она остаётся осмысленной, пока меньше половины данных испорчено.
У обычного σ точка слома 0 % — один достаточно большой выброс портит её как угодно
сильно.

### Бегущая медиана

`O(n·log w)` через упорядоченный список с бинарным поиском: при сдвиге окна один элемент
удаляется, один вставляется. Края зажимаются (окно укорачивается).

Применение — разделение импульсного и стационарного, см. [05](05-Акустика-щелчки.md) §4.

### Автокорреляция на лаге 1

```
ρ = Σ_{i≥1}(xᵢ − x̄)(xᵢ₋₁ − x̄) / Σ(xᵢ − x̄)²
```

Результат зажимается в [−0.999, 0.999], чтобы формула `n(1−ρ)/(1+ρ)` не взорвалась.

## 9.8. Линейный детренд

```
Σx = n(n−1)/2
Σx² = (n−1)n(2n−1)/6
slope = (n·Σxy − Σx·Σy) / (n·Σx² − (Σx)²)
```

Замкнутые формулы для `x = 0..n−1` — без выделения памяти под ось.

Обязателен перед любым FFT дрейфующего ряда: тренд создаёт разрыв между началом и концом
периодического продолжения, чей спектр `1/f` размазывается по низким бинам и хоронит там
слабый пик вращения.

## 9.9. Скользящее окно

Код: `Dsp/TimeWindow.cs`

Кольцевой буфер с двумя ограничителями: по времени (`WindowSeconds`) и по числу элементов
(`MaxCount`). Второй нужен как страховка от устройства, отдающего сэмплы вдесятеро
чаще ожидаемого.

Вытеснение старых элементов зависит **только от timestamp'ов сэмплов**:

```
пока  t_новейший − t_старейший > WindowSeconds:  выбросить старейший
```

Никакого обращения к системным часам — иначе воспроизведение записи «за миллисекунды»
(тесты §7.5) давало бы совсем другое содержимое окна, чем реальный захват.

Все оценщики пересчитываются **по счётчику сэмплов**, а не по таймеру. Это требование
детерминированности: прогон одних и тех же данных должен давать бит-в-бит одинаковый
результат независимо от скорости подачи. Ни одного обращения к системным часам внутри
Core — время берётся только из timestamp'ов сэмплов.

## 9.10. Что проверяют тесты примитивов

Спецификация §7.3 требует численных тестов для каждого блока. Проверяемые свойства:

| Примитив | Проверка |
|---|---|
| FFT | против аналитически известных спектров; амплитуда синуса на бине читается точно |
| Развёртка фазы | скачки через ±π восстанавливаются; выброс не сдвигает хвост (`UnwrapSteady`) |
| Параболическая интерполяция | парабола с известной вершиной восстанавливается точно |
| Подгонка эллипса | точки на известном эллипсе → параметры восстановлены; дуга не даёт гиперболу |
| Фильтры | АЧХ по отклику на набор синусов; −3 дБ ровно на срезе |
| Круговое среднее | корректность на данных, пересекающих границу свёртки |
| Робастная регрессия | наклон не сдвигается выбросами; σ не занижена на чистых данных |
| Ресемплинг | ускорение на известный фактор даёт известное смещение в центах |
