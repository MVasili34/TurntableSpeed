## 2.1. Физика: почему магнитометр, а не гироскоп

Магнитное поле Земли **B** в лабораторной системе координат постоянно: примерно 25–65 мкТл,
направление фиксировано (в средних широтах — наклон 60–70° к горизонту).

Телефон лежит на диске и вращается вместе с ним. В **собственных осях телефона** тот же
самый неподвижный вектор поля выглядит вращающимся с той же угловой скоростью, но в
обратную сторону:

```
B_телефона(t) = R(−ωt) · B_Земли
```

где `R` — матрица поворота вокруг оси вращения диска (вертикали).

Разложим `B_Земли` на составляющую вдоль оси вращения и перпендикулярную ей:

```
B = B_∥ · ê + B_⊥
```

* `B_∥` при вращении **не меняется** — это проекция на ось.
* `B_⊥` **описывает окружность** радиуса `|B_⊥|` в плоскости, перпендикулярной оси.

Значит траектория конца вектора в осях телефона — окружность в некоторой плоскости, и
телефон делает по ней ровно один полный оборот за один оборот диска.

**Ключевой момент.** Измеряемая величина — не амплитуда `|B_⊥|` (она нам совершенно
безразлична, и её масштабная ошибка нас не волнует), а **скорость набега фазы** по этой
окружности. Фаза набегает на ровно 2π за оборот — это геометрический факт, не зависящий
ни от чувствительности датчика, ни от силы поля, ни от широты. Единственное, от чего
зависит результат — это **шкала времени**, а она берётся из кварцевого генератора
телефона с точностью единиц ppm (0.0001 %).

Отсюда главный архитектурный вывод: **у магнитометрического метода нет ошибки
масштабного коэффициента по построению.** У гироскопического есть, и она 1–3 %.

## 2.2. Что мешает и как это лечится

| Помеха | Физика | Лечение |
|---|---|---|
| **Hard iron** | Постоянный намагниченный материал рядом с датчиком (динамик телефона, магнит мотора проигрывателя, намагниченный диск) добавляет постоянный вектор. Окружность смещается из начала координат. | Смещение = центр подогнанного эллипса |
| **Soft iron** | Ферромагнетик рядом искажает поле анизотропно. Окружность превращается в эллипс. | Эллиптичность = оси подогнанного эллипса |
| **Ось наклонена** | Телефон лежит не идеально, ось вращения не совпадает с осью Z датчика. | PCA: плоскость находится из данных |
| **Кратковременные помехи** | Мимо проносят магнит, включается мотор. | Отбраковка по радиусу + робастная регрессия |
| **Медленный дрейф** | Уход нуля датчика, перемещение железа в комнате. | Учёт автокорреляции остатков в σ |

Первые два лечатся одним и тем же приёмом, и это красиво: **hard iron — это центр
эллипса, soft iron — это его форма.** Одна подгонка даёт обе калибровки.

## 2.3. Шаг 1 — PCA: найти плоскость вращения

Код: `Dsp/PrincipalAxes.cs`

Мы не знаем, как телефон ориентирован относительно оси вращения. Но мы знаем, что
траектория `(mx, my, mz)` лежит в **плоскости**. Значит облако точек плоское, и его можно
найти методом главных компонент.

Считается выборочная ковариационная матрица трёхмерного облака:

```
μ = (1/n) Σ mᵢ

C = 1/(n−1) · Σ (mᵢ − μ)(mᵢ − μ)ᵀ      (симметричная 3×3)
```

Её собственные значения `λ₀ ≥ λ₁ ≥ λ₂` и собственные векторы `v₀, v₁, v₂` дают:

* `v₀, v₁` — базис плоскости вращения (`PlaneU`, `PlaneV`);
* `v₂` — **нормаль к плоскости, то есть ось вращения** (`Normal`);
* `λ₀, λ₁ ≈ |B_⊥|²/2` — разброс в плоскости;
* `λ₂ ≈ σ_шума²` — разброс поперёк плоскости, в идеале только шум.

Диагностика плоскостности:

```
Flatness = λ₂ / λ₀
```

Если она близка к нулю — точки действительно лежат в плоскости, предпосылка метода
выполнена. Если она заметна (в коде порог для уверенности — 0.05) — телефон не следует
жёстко одной оси вращения: соскальзывает, диск бьёт, или это вообще не вращение.

`μ` — это первое приближение hard-iron смещения (центроид облака).

### Решение задачи на собственные значения

Матрица 3×3 симметричная, поэтому используется **циклический метод Якоби**
(`SymmetricEigen3.Decompose`). Идея: последовательными вращениями Гивенса

```
J(p,q,θ):  обнуляет внедиагональный элемент a[p,q]
```

матрица приводится к диагональной. Угол выбирается из условия `a'[p,q] = 0`:

```
θ = (a_qq − a_pp) / (2·a_pq)
t = sign(θ) / (|θ| + √(θ² + 1))        (корень квадратного уравнения, меньший по модулю)
c = 1/√(t² + 1),   s = t·c
```

Выбор меньшего корня — стандартный приём для устойчивости: он даёт вращение на угол
меньше 45°, накопление ошибок минимально. Метод сходится квадратично; кода на 24 свипа
хватает с огромным запасом. Накопленные вращения дают матрицу собственных векторов.

Почему Якоби, а не что-то из библиотеки: он умещается в 100 строк без зависимостей,
абсолютно детерминирован и для 3×3 быстрее любого общего алгоритма.

### Проекция на плоскость

```
u = (m − μ) · v₀
v = (m − μ) · v₁
```

Дальше вся работа идёт в двумерных координатах `(u, v)`.

## 2.4. Шаг 2 — подгонка эллипса: hard iron и soft iron

Код: `Dsp/EllipseFit.cs`

### Постановка

В плоскости точки должны лежать на окружности, но из-за soft iron лежат на эллипсе, а
из-за hard iron он смещён. Общее коническое сечение:

```
A·x² + B·x·y + C·y² + D·x + E·y + F = 0
```

Шесть коэффициентов с точностью до общего множителя — пять степеней свободы, ровно
столько, сколько у эллипса (центр 2, полуоси 2, угол 1).

### Почему не «просто МНК»

Наивный подход — минимизировать `Σ (A xᵢ² + ... + F)²` при каком-нибудь условии
нормировки вроде `|a| = 1` — имеет фатальный дефект: **решение может оказаться гиперболой
или параболой**. Особенно если дуга неполная. А неполная дуга у нас бывает регулярно: на
78 rpm за 2 секунды окна проходит меньше трёх оборотов, а в самом начале измерения —
меньше одного.

### Решение: метод Фицгиббона в формулировке Халиржа–Флюссера

Накладывается **эллипс-специфичное** ограничение:

```
4AC − B² = 1
```

Дискриминант конического сечения `B² − 4AC` отрицателен ровно для эллипса. Зафиксировав
его равным `−1`, мы делаем невозможным получение гиперболы: **решение эллипс по
построению**. Заодно это фиксирует масштаб, снимая тривиальное решение `a = 0`.

Задача становится:

```
минимизировать  aᵀ S a   при   aᵀ C₁ a = 1
```

где `S = DᵀD` — матрица рассеяния, `D` — матрица дизайна со строками
`(x², xy, y², x, y, 1)`, а `C₁` — матрица ограничения.

Метод Лагранжа даёт обобщённую задачу на собственные значения `S a = λ C₁ a`. Прямое её
решение численно неустойчиво (`S` почти вырождена). Халирж и Флюссер разбили `a` на
квадратичную и линейную части `a = (a₁, a₂)` и свели задачу к обычной 3×3:

```
S₁ = D₁ᵀD₁,  S₂ = D₁ᵀD₂,  S₃ = D₂ᵀD₂

T = −S₃⁻¹ S₂ᵀ                  (линейная часть выражается через квадратичную)
M = S₁ + S₂ T                  (редуцированная 3×3)
M' = C₁⁻¹ M                    (в коде — явная перестановка строк)
```

`C₁⁻¹` для ограничения `4AC − B² = 1` — это просто перестановка со множителями, поэтому в
коде она записана вручную:

```csharp
constrained[0, col] =  0.5 * m[2, col];
constrained[1, col] = -1.0 * m[1, col];
constrained[2, col] =  0.5 * m[0, col];
```

Дальше ищется собственный вектор `M'`, удовлетворяющий `4a₀a₂ − a₁² > 0`. Он ровно один.
Линейная часть восстанавливается как `a₂ = T·a₁`.

### Обусловленность: обязательная нормировка

Сырые значения магнитометра — десятки мкТл. Тогда `x²` — тысячи, а свободный член — 1.
Разброс элементов матрицы рассеяния — шесть порядков, и `S₃` численно вырождается.

Поэтому перед подгонкой данные центрируются и масштабируются:

```
x' = (x − x̄) / s,   s = √( (1/n) Σ [(xᵢ−x̄)² + (yᵢ−ȳ)²] )
```

то есть на RMS-радиус облака. После подгонки нормировка отменяется:

```
centre = centre' · s + mean
semiAxis = semiAxis' · s
```

Это не косметика — без неё метод просто не работает на реальных данных.

### Из коэффициентов в геометрию

`EllipseFit.FromConic`:

```
Δ  = B² − 4AC                        (< 0 для эллипса)
x₀ = (2CD − BE) / Δ
y₀ = (2AE − BD) / Δ
F₀ = F + ½(D·x₀ + E·y₀)              (свободный член после сдвига в центр)
```

Квадратичная форма `[[A, B/2], [B/2, C]]` диагонализуется аналитически:

```
tr = A + C,   det = AC − B²/4
λ₁,₂ = ½ (tr ± √(tr² − 4·det))
```

Полуоси:

```
aᵢ = √(−F₀ / λᵢ)
```

Бо́льшему собственному значению отвечает **меньшая** полуось (жёстче квадратичная форма →
короче ось). Угол — из собственного вектора.

### Что это даёт для калибровки

```
CenterX, CenterY  →  hard iron (в координатах плоскости)
SemiMajor/SemiMinor = AxisRatio  →  soft iron (1.0 = идеальная окружность)
ResidualRms  →  насколько модель вообще описывает данные
```

Hard iron поднимается обратно в оси телефона (`ComputeHardIron`):

```
offset = μ + x₀·v₀ + y₀·v₁
```

### Нормализация точки: главная операция

`EllipseFitResult.Normalize` переводит измеренную точку на **единичную окружность**:

1. вычесть центр (снять hard iron);
2. повернуть в собственные оси эллипса на `−angle`;
3. поделить координаты на полуоси (снять soft iron);
4. повернуть обратно.

```
(u, v) = R(−θ)·(x − x₀, y − y₀)
(u', v') = (u / a, v / b)
(nx, ny) = R(+θ)·(u', v')
```

Смысл: **после этой операции фаза набегает равномерно.** Именно это и требуется линейной
регрессии дальше. Без снятия эллиптичности фаза «дышала» бы дважды за оборот, и регрессия
получила бы синусоидальный остаток с частотой `2ω`, который не смещает наклон в среднем,
но раздувает оценку дисперсии.

## 2.5. Шаг 3 — отбраковка выбросов по радиусу

После подгонки для каждой точки считается нормализованный радиус:

```
r = |Normalize(u, v)|
```

Идеальная точка даёт ровно 1. Точки с `|r − 1| > 0.35` выбрасываются.

**Почему это делается ДО взятия фазы, а не поручается робастной регрессии.** Это тонкое
место, и в коде оно прокомментировано отдельно. Развёртка фазы (unwrap) **кумулятивна**:
если один отсчёт отброшен магнитом на полоборота в сторону, то классический unwrap
припишет ему не тот 2π-виток, и **все последующие точки сдвинутся на 2π**. Это не выброс,
это ступенька уровня. Веса Хьюбера ступеньку не отбраковывают — они рассчитаны на
одиночные отскоки, а не на сдвиг половины выборки.

Магнитная помеха меняет **величину** поля, поэтому она проявляется в радиусе раньше, чем
успевает испортить фазу. Это дёшево и надёжно.

Предохранитель: если отбраковано больше 50 % — значит подозрителен не сигнал, а сам
эллипс. Тогда фильтр **не применяется вообще**, и плохая подгонка честно уезжает
в диагностику (`ellipseResidualRms`, `rejectedFraction`), вместо того чтобы быть
замазанной.

## 2.6. Шаг 4 — фаза и её развёртка

Код: `Dsp/PhaseMath.cs`

Фаза точки:

```
φ = atan2(ny, nx)  ∈ (−π, π]
```

Это пилообразная функция: раз в оборот она прыгает с `+π` на `−π`. Нужно её развернуть в
непрерывную линейно растущую.

### Наивный unwrap и его беда

```
φ_unwrapped[i] = φ_unwrapped[i−1] + wrap(φ[i] − φ_unwrapped[i−1])
```

где `wrap` сворачивает в `(−π, π]`. Работает идеально при шуме и катастрофически при
выбросах: шаг ограничен ±π **по построению**, поэтому отсчёт, отскочивший больше чем на
полоборота, не даёт большого шага — он тихо съедает 2π накопленной фазы и сдвигает весь
хвост записи.

### Робастная альтернатива: `UnwrapSteady`

Ключевое наблюдение: диск крутится **равномерно**. Значит вместо цепочки от предыдущего
отсчёта можно ставить каждый отсчёт на ту 2π-ветвь, которая ближе к **предсказанию**:

```
φ_unwrapped[i] = φ_предск[i] + wrap(φ[i] − φ_предск[i])
```

Тогда испорченный отсчёт стоит только своего собственного остатка и никого за собой не
тянет.

Предсказание даёт **α–β фильтр** (упрощённый фильтр Калмана для модели «постоянная
скорость»):

```
предсказание:  φ̂ = level + rate·Δt
инновация:     ι = wrap(φ_измер − φ̂)

выход:         φ_unwrapped[i] = φ̂ + ι          ← полная инновация, это остаток
коррекция:     ι_clip = clamp(ι, ±0.6 рад)     ← ограниченная, чтобы выброс не сдвинул трекер
               level = φ̂ + α·ι_clip
               rate  = rate + β·ι_clip / Δt
```

с `α = 0.08`, `β = α²/2`. Соотношение `β ≈ α²/2` — стандартный выбор,
дающий примерно критическое демпфирование: трекер следует за реальными изменениями
скорости, но не раскачивается.

Два важных решения:

1. **Измерению отдаётся полная инновация.** Это его остаток; насколько ему верить —
   решает регрессия ниже по потоку, а не трекер. Трекер не имеет права «чинить» данные.
2. **Трекеру отдаётся ограниченная инновация.** Ограничение симметричное, поэтому оно
   ничего не смещает — оно лишь не даёт поверить выбросу.

Начальная скорость трекера берётся не абы откуда, а из **медианы пошаговых скоростей**:

```
rate₀ = median{ wrap(φᵢ − φᵢ₋₁) / Δtᵢ }
```

Медиана устойчива к любому количеству одиночных выбросов до 50 %. Ограничение метода:
`|ω·Δt| < π`, то есть нужно **больше двух отсчётов на оборот** — условие Найквиста для
фазы. При 50 Гц и 78 rpm получается 38 отсчётов на оборот, запас огромный.

Компромисс между двумя подходами явно назван в коде: цепочка идеальна при шуме и
безнадёжна при выбросах; привязка к одной глобальной прямой — наоборот, потому что наклон
этой прямой сам оценивается по тем же испорченным данным. α–β трекер — середина.

## 2.7. Шаг 5 — регрессия фазы: собственно измерение

Код: `Dsp/LineFit.cs`

Развёрнутая фаза линейна во времени:

```
φ(t) = ω·t + φ₀
```

Угловая скорость — **наклон**. Это и есть измерение.

### Взвешенный МНК

```
ω̂ = (Σw Σwxy − Σwx Σwy) / (Σw Σwx² − (Σwx)²)
```

Дисперсия остатков и стандартная ошибка наклона:

```
s² = Σ wᵢ rᵢ² / (n − 2)
Var(ω̂) = s² · Σw / (Σw Σwx² − (Σwx)²)
```

Веса нормируются так, чтобы среднее было 1 — тогда `s²` остаётся интерпретируемой как
дисперсия остатка, а не зависит от того, в каких единицах заданы веса.

**Из этого напрямую получается доверительный интервал на скорость** — то самое, чего
требует спецификация. Никакой отдельной эвристики не нужно: `SE(ω̂)` переводится в rpm
тем же множителем `60/2π`, что и сама `ω`.

### Робастность: IRLS с весами Хьюбера

Мимо проносят магнит — фаза дёргается. Обычный МНК квадратично штрафует остатки, поэтому
один сильный выброс наклоняет всю прямую.

Функция потерь Хьюбера квадратична вблизи нуля и **линейна** за порогом:

```
ρ(r) = ½r²           при |r| ≤ k
     = k|r| − ½k²    при |r| > k
```

В виде итеративно перевзвешенного МНК (IRLS) это эквивалентно весам:

```
wᵢ = 1              при |rᵢ| ≤ k·s
   = k·s / |rᵢ|     при |rᵢ| > k·s
```

Масштаб `s` берётся робастно — через **медианное абсолютное отклонение**:

```
MAD = 1.4826 · median|rᵢ − median(r)|
```

Множитель 1.4826 = `1/Φ⁻¹(0.75)` делает MAD состоятельной оценкой σ для нормальных данных
(для стандартного нормального медиана `|x|` равна 0.6745, и `1/0.6745 = 1.4826`).

Константа `k = 1.345` — классический выбор: даёт **95 % эффективности** относительно МНК
на чисто нормальных данных при существенной устойчивости к засорению. Сходимость обычно
за 3–5 итераций.

### Ошибка M-оценки: тонкость, которую легко пропустить

IRLS заканчивается взвешенной подгонкой, и соблазнительно взять её стандартную ошибку как
есть. Это неверно.

Взвешенная формула считает веса **известными точностями наблюдений**. А они не известны —
они функция самих остатков. Дисперсия остатков `Σw r²/(n−2)` занижена ровно на ту
величину, на которую мы придавили большие остатки. На чистых нормальных данных интервал
получается **примерно на 10 % у́же правды**. Для главного инструмента приложения это
недопустимо: оценка была бы точной, а заявленная неопределённость — ложью.

Правильный масштаб для M-оценки (`WithRobustStandardErrors`):

```
τ² = E[ψ²] / (E[ψ'])²
```

где `ψ(r) = clamp(r, ±k·s)` — производная функции потерь, а `ψ'` равна 1 внутри порога и 0
снаружи. В коде:

```
E[ψ²]  = (1/n) Σ clamp(rᵢ, ±k·s)²
E[ψ']  = (доля точек внутри порога)
```

Дальше стандартно:

```
Var(ω̂) = τ² / Σ(xᵢ − x̄)²
```

На чистых нормальных данных это даёт результат на **2.6 % выше** обычного МНК — это
честная цена робастности, а не 10 % ниже, что было бы самообманом.

### Автокорреляция остатков

Остатки фазы не белые: медленное магнитное блуждание, эксцентриситет диска, зубцовый
момент мотора — всё это создаёт коррелированные во времени отклонения. Считать такие
точки независимыми — значит занизить интервал, потому что `SE ~ 1/√n` требует именно
независимости.

Считается автокорреляция остатков на лаге 1:

```
ρ = Σ(rᵢ − r̄)(rᵢ₋₁ − r̄) / Σ(rᵢ − r̄)²
```

и вводится **эффективный размер выборки** (стандартный результат для AR(1)):

```
n_эфф = n · (1 − ρ) / (1 + ρ)
```

Смысл: у процесса AR(1) дисперсия среднего в `(1+ρ)/(1−ρ)` раз больше, чем у белого шума.
При `ρ = 0.5` эффективная выборка втрое меньше номинальной. Стандартная ошибка
раздувается:

```
SE_испр = SE · √(n / n_эфф)
```

При `ρ ≤ 0` коррекция не применяется (отрицательная корреляция интервал бы сузила — не
будем этим пользоваться, это было бы оптимистично).

## 2.8. Оценка уверенности

Пять частных показателей, каждый в [0, 1]:

| Фактор | Формула | Что ловит |
|---|---|---|
| `precision` | `1 − (SE/rpm)/0.0005 · 0.5` | достигнута ли целевая относительная точность |
| `coverage` | `revolutions / 6` | накоплено ли достаточно оборотов |
| `geometry` | `(1 − res/0.15)·(1 − (ratio−1)/1.5)` | хороша ли подгонка эллипса |
| `planarity` | `1 − flatness/0.05` | лежат ли точки в плоскости |
| `cleanliness` | `1 − outlierFraction/0.2` | много ли выбросов |

Итог — **геометрическое среднее**:

```
confidence = (precision · coverage · geometry · planarity · cleanliness)^(1/5)
```

Почему геометрическое, а не арифметическое: одна плохая компонента должна утянуть
результат вниз, а не быть усреднённой с четырьмя хорошими. Геометрическое среднее
обращается в ноль, если хоть один множитель нулевой — ровно то поведение, которое нужно.
(В коде каждый множитель прижат снизу к `1e-9`, чтобы не получить NaN.)

`coverage = revolutions/6` отражает физику: примерно до 3 оборотов фазовая прямая ещё не
усреднила эксцентриситет диска и зубцовый момент мотора — они периодичны с периодом
оборота.

## 2.9. Требования к окну и почему они такие

| Параметр | Значение | Обоснование |
|---|---|---|
| `WindowSeconds` | 60 | ≈33 оборота при 33⅓ — цель «лучше 0.05 % за минуту» |
| `MinimumSpanSeconds` | 2 | короче — фазовая прямая слишком коротка |
| `MinimumRevolutions` | 1 | **обязательно** (см. ниже) |
| `MinimumSamples` | 64 | статистика регрессии |
| `RecomputeEverySamples` | 25 | детерминированность (см. ниже) |

**Почему минимум один оборот.** При неполной дуге смещение центра эллипса и кривизна дуги
**не разделимы**: короткая дуга большого круга без центра неотличима от дуги малого круга
со смещённым центром. Подгонка радостно выдумает какой-нибудь центр, и он будет неверен.
Только замкнутая петля фиксирует и центр, и радиус.

**Почему пересчёт по счётчику сэмплов, а не по времени.** Требование
детерминированности: прогон одних и тех же данных должен давать бит-в-бит одинаковый
результат, независимо от того, насколько быстро эти данные подаются. Ни одного обращения
к системным часам внутри Core.

## 2.10. Итоговый конвейер

```
(t, mx, my, mz) @ 50–100 Гц
        ↓
    TimeWindow (60 с скользящее окно)
        ↓
    PCA → плоскость вращения + ось + flatness
        ↓
    проекция на плоскость → (u, v)
        ↓
    EllipseFit → центр (hard iron), полуоси (soft iron), угол
        ↓
    отбраковка по радиусу |r − 1| > 0.35
        ↓
    повторные PCA + EllipseFit по очищенным данным
        ↓
    Normalize → фаза φ = atan2(ny, nx)
        ↓
    UnwrapSteady (α–β трекер + привязка к ветви)
        ↓
    RobustLineFit.Huber → ω = наклон, SE(ω)
        ↓
    коррекция SE на автокорреляцию остатков
        ↓
    rpm = ω · 60/(2π),  SE_rpm = SE(ω) · 60/(2π)
        ↓
    классификация номинала + оценка уверенности
```
