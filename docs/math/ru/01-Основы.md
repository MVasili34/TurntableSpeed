# 1. Основы: величины, единицы, классификация

Код: `TurntableSpeed.Core/Contracts/NominalSpeed.cs`, `SpeedEstimate.cs`

---

## 1.1. Что вообще измеряется

Диск проигрывателя — твёрдое тело, вращающееся вокруг неподвижной оси. У твёрдого тела
**угловая скорость ω одинакова во всех точках**. Линейная скорость `v = ω·r` зависит от
радиуса, угловая — нет.

Практическое следствие, которое нужно сказать пользователю: **где именно лежит телефон на
диске и насколько он отцентрован — не влияет на точность** гироскопа и магнитометра. Оба
измеряют угловую величину. Смещение от центра влияет только на механическую балансировку
(и на центростремительное ускорение, см. [04](04-Акселерометр.md)).

Измеряемая величина — скорость `n` в оборотах в минуту (rpm). Все остальные формы —
производные:

| Величина                    | Формула                          | Обозначение в коде |
|-----------------------------|----------------------------------|---|
| Обороты в секунду (частота) | `f = n / 60`                     | `RevolutionsPerSecond` |
| Период оборота              | `T = 60 / n`                     | `PeriodSeconds` |
| Градусы в секунду           | `360 * f = 360 * n / 60 = n · 6` | `DegreesPerSecond` |
| Угловая скорость            | `ω = 2π·n / 60`                  | `RadiansPerSecond` |

Обратные преобразования (`SpeedMath`):

```
n = ω · 60 / (2π)      RpmFromRadiansPerSecond
n = 60 / T             RpmFromPeriod
```

Три номинала:

| Номинал | rpm (точно) | об/с | °/с | рад/с | Период, с |
|---|---|---|---|---|---|
| 33⅓ | 100/3 | 0.555556 | 200.000 | 3.490659 | 1.800000 |
| 45 | 45 | 0.750000 | 270.000 | 4.712389 | 1.333333 |
| 78 | 78 | 1.300000 | 468.000 | 8.168141 | 0.769231 |

В коде 33⅓ хранится как `100.0 / 3.0`, а не как `33.33`: округление здесь дало бы
систематическую ошибку 0.01 %, сопоставимую с целевой точностью 0.1 %.

## 1.2. Скорость и высота тона: почему центы

> Если понятия «цент», «октава», «равномерная темперация» непривычны — весь этот аппарат
> разобран с нуля в [00-Теория-звука.md](00-Теория-звука.md). Здесь дана только выжимка.

Если проигрыватель крутится в `(1 + e)` раз быстрее номинала, то вся запись
воспроизводится в `(1 + e)` раз быстрее, а значит все частоты умножаются на тот же
множитель:

```
f_воспр = f_записи · (1 + e)
```

Человеческое восприятие высоты логарифмическое: слух реагирует на **отношения** частот, а
не на их разности (переход 100→200 Гц и 400→800 Гц — один и тот же музыкальный интервал,
хотя разности отличаются вчетверо). Поэтому единица измерения высоты обязана быть
отношением, а чтобы интервалы можно было складывать, а не перемножать, — от этого
отношения берут логарифм.

Музыкальная единица — **цент**, одна сотая полутона равномерной темперации. Октава — это
отношение частот `2:1`; она делится на 12 равных полутонов, значит полутон — это
`2^(1/12)` (+5.946 %), а цент — `2^(1/1200)` (+0.0578 %). В октаве 1200 центов. Отсюда:

```
центы = 1200 · log₂(1 + e)
```

и обратно

```
e = 2^(центы/1200) − 1
```

Код: `SpeedMath.CentsFromRelativeDeviation` / `RelativeDeviationFromCents`.

Полезные ориентиры:

| Отклонение | Центы |
|---|---|
| +0.1 % | +1.73 |
| +0.3 % | +5.19 |
| +1 % | +17.23 |
| +2 % | +34.3 |
| +5.95 % | +100 (ровно полутон) |

Для малых `e` разложение `log₂(1+e) ≈ e/ln2` даёт линейное приближение
`центы ≈ 1731·e`, то есть **1 % ≈ 17.3 цента**. Но в коде используется точная формула:
при отклонениях в единицы процентов линеаризация уже врёт в третьем знаке.

Обратите внимание на асимметрию: `+1 %` даёт `+17.23` цента, а `−1 %` даёт `−17.40`.
Логарифм не симметричен, и именно поэтому производная (нужная для переноса погрешности,
см. [06](06-Акустика-строй.md)) берётся в точке измерения, а не считается константой.

## 1.3. Классификация: какой это номинал

Дано измеренное `n`. Нужно понять, это «33⅓ с отклонением» или «45 с отклонением», и
насколько уверенно.

Для каждого кандидата считается относительное отклонение в процентах:

```
d_k = (n − N_k) / N_k · 100
```

Побеждает кандидат с минимальным `|d|`. Дальше — два вопроса, на которые нужно ответить
честно.

### Вопрос 1: а вообще ли это турнтейбл-скорость?

Если `|d_best| > 8 %`, номинал не присваивается вообще (`Nominal = null`). Порог 8 %
выбран так, чтобы **середина между 33⅓ и 45 не попадала ни в одну полосу**:

```
середина = (33.333 + 45) / 2 = 39.167
от 33⅓:  (39.167 − 33.333)/33.333 = +17.5 %
от 45:   (39.167 − 45)/45        = −13.0 %
```

Обе величины больше 8 %, значит скорость ровно посередине честно остаётся
неклассифицированной. Это прямое требование спецификации (§7.2).

### Вопрос 2: насколько отрыв от второго кандидата убедителен

Пусть `d₁ = |d_best|`, `d₂ = |d_runner-up|`. Мера разделения:

```
separation = (d₂ − d₁) / (d₂ + d₁)
```

Это нормированный контраст: он равен 0 при `d₁ = d₂` (равноудалённость — полная
неопределённость) и стремится к 1, когда победитель гораздо ближе. Плюс штраф за то, что
и победитель-то далековат:

```
proximity  = 1 − min(1, d₁ / tolerance)
confidence = separation · (0.5 + 0.5 · proximity)
```

Множитель `(0.5 + 0.5·proximity)` устроен так, что близость может уменьшить уверенность
максимум вдвое: главный аргумент — всё-таки отрыв от конкурента, а не абсолютная
близость к номиналу (проигрыватель может реально идти на 5 % мимо).

## 1.4. Контракт результата

```csharp
sealed record SpeedEstimate(
    double RevolutionsPerMinute,   // точечная оценка
    double StandardError,          // 1σ, те же единицы
    NominalSpeed? Nominal,         // 33⅓ / 45 / 78 / null
    double DeviationPercent,       // от Nominal
    double Confidence,             // 0..1
    IReadOnlyDictionary<string, double> Diagnostics);
```

Производные свойства:

```
DeviationCents        = 1200·log₂(1 + DeviationPercent/100)
Margin95              = 1.959964 · StandardError      // половина 95 % интервала
LowerBound95          = rpm − Margin95
UpperBound95          = rpm + Margin95
StandardErrorPercent  = StandardError / rpm · 100
```

Коэффициент 1.959964 — это квантиль `z_{0.975}` стандартного нормального распределения.
Нормальность здесь оправдана: все оценки в проекте — это либо наклон регрессии по сотням
точек, либо среднее по многим отсчётам, то есть работает ЦПТ.

`SpeedEstimate.FromRpm` не просто складывает поля, а домножает уверенность оценщика на
уверенность классификации:

```
Confidence = confidence_оценщика · (0.35 + 0.65 · confidence_классификации)
```

Логика: даже если оценщик отработал идеально, но скорость сидит ровно между номиналами,
итоговая уверенность должна упасть — но не до нуля, потому что само число `rpm` при этом
измерено прекрасно. Отсюда пол 0.35.

## 1.5. Целевая точность и что она значит

| Режим | Цель | Что это в центах | Что это в rpm при 33⅓ |
|---|---|---|---|
| Сенсорный | ±0.1 % | ±1.7 | ±0.033 |
| Акустический | ±0.3 % | ±5.2 | ±0.100 |

Для сравнения: типичный слышимый порог расстройки для музыкального слуха — порядка 5–10
центов на одновременно звучащих тонах (механизм — биения, см.
[00 §0.9](00-Теория-звука.md)). То есть акустический режим целится примерно в порог
слышимости, а сенсорный — заметно ниже его.

Отсюда же следует, почему **гироскопу нельзя верить абсолютно**: его заводская ошибка
масштаба 1–3 % — это 17–52 цента, в 10–30 раз больше целевой точности. Подробно
в [03](03-Гироскоп.md).
